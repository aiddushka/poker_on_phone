# Отчет по проекту "PockerLAN - Mental Poker"

## 1. Цель работы

Разработать кроссплатформенное мобильное приложение (Flutter, Android/iOS) для многопользовательской игры в покер по LAN с элементами криптографической защиты, используя идеи mental poker и алгоритм SRA.

[ИЗОБРАЖЕНИЕ:ГЛАВНЫЙ ЭКРАН ПРИЛОЖЕНИЯ (МЕНЮ СОЗДАНИЯ И ПОДКЛЮЧЕНИЯ)]

## 2. Краткое описание приложения

Приложение реализует LAN-игру в формате Texas Hold'em:

- хост создает стол (сервер);
- клиенты подключаются по IP и порту;
- игра проходит по этапам Preflop -> Flop -> Turn -> River -> Showdown;
- есть интерфейс ставок, действий игроков и окно итогов;
- поддерживаются языки RU/EN.

## 4. Логика игры (Texas Hold'em)

### 4.1 Этапы раздачи

- Preflop: каждому игроку выдаются 2 закрытые карты.
- Flop: открываются 3 общие карты.
- Turn: открывается 4-я общая карта.
- River: открывается 5-я общая карта.
- Showdown: сравнение комбинаций.

### 4.2 Игровые действия

- Fold (сброс) - игрок выходит из текущей раздачи.
- Check - пропуск без ставки (когда текущая ставка уже уравнена).
- Call - уравнивание текущей ставки.
- Raise - повышение ставки.

### 4.3 Завершение раздачи

Раздача завершается, если:

1. Остался один активный игрок (остальные сделали Fold), либо
2. Дойдены этапы до Showdown и определен победитель по комбинации.

После завершения показывается окно результата; хост может запускать новую игру, клиенты ждут старта.

## 5. Криптографическая часть: SRA

## 5.1 Теоретическая идея SRA в mental poker

SRA (Shamir-Rivest-Adleman в контексте mental poker) использует коммутативное шифрование:

- каждый игрок имеет собственную пару ключей;
- карту можно шифровать последовательно ключами разных игроков;
- порядок шифрования/дешифрования согласован так, что каждый игрок снимает только свой слой;
- ни один участник не должен иметь полный контроль над колодой в открытом виде.

Формально для модуля `p`:

- шифрование: `c = m^e mod p`
- дешифрование: `m = c^d mod p`
- выполняется условие `e * d = 1 mod (p - 1)`
- при правильно выбранных параметрах операции совместимы с многосторонней схемой.

## 5.2 Реализация в коде

Криптомодуль реализован в файле:

- `lib/crypto/sra.dart`

### 5.2.1 Структуры и методы

1. `SraKeyPair`
   - `primeModulus`
   - `publicExponent`
   - `privateExponent`
   - `encrypt(BigInt plain)` -> `plain.modPow(publicExponent, primeModulus)`
   - `decrypt(BigInt cipher)` -> `cipher.modPow(privateExponent, primeModulus)`

2. `SraCrypto`
   - `generateKeyPair({BigInt? primeModulus})`
   - `encodeCardId(int cardId)` (переход к `BigInt`)
   - `decodeCardId(BigInt encoded)` (обратный переход)
   - внутренние функции `_gcd` и `_modInverse`

### 5.2.2 Генерация ключа

В `generateKeyPair`:

- выбирается модуль `p` (по умолчанию `65537`);
- вычисляется `phi = p - 1`;
- подбирается экспонента `e`, взаимно простая с `phi` (`gcd(e, phi) = 1`);
- вычисляется закрытая экспонента `d = e^{-1} mod phi`.

Так формируется пара `(e, d)` для операций модульного возведения в степень.

### 5.2.3 Шифрование идентификаторов карт

Карта представляется числом (`cardId`), затем:

1. `cardId` -> `BigInt` через `encodeCardId`;
2. применяется `encrypt(...)`;
3. для получения исходного идентификатора используется `decrypt(...)` + `decodeCardId(...)`.

[ИЗОБРАЖЕНИЕ:СХЕМА ШИФРОВАНИЯ КАРТЫ cardId -> BigInt -> encrypt -> cipher]

## 5.3 Где именно в проекте используется SRA

### 5.3.1 Реально реализовано

- Полный набор базовых SRA-операций реализован в `lib/crypto/sra.dart`.
- Модуль готов для интеграции в сетевой протокол mental poker.

### 5.3.2 Текущее состояние интеграции в игровой процесс

В текущей версии:

- игровой раунд в `lib/ui/game_room_page.dart` формирует колоду через обычный `shuffle`;
- карта передается как обычный числовой ID;
- вызовы `SraCrypto` в потоке раздачи/обмена сообщениями пока не встроены.

Это означает, что на данном этапе криптомодуль **реализован**, но **используется как готовая подсистема**, ожидающая полной интеграции в многосторонний протокол раздачи.

## 5.4 Как должна выглядеть полная интеграция SRA (логика применения)

Для полного соответствия mental poker на практике нужен следующий протокол:

1. Инициализация:
   - каждый игрок генерирует свою SRA-пару ключей.

2. Совместное шифрование колоды:
   - исходная колода кодируется в числа;
   - каждый игрок по очереди шифрует всю колоду своим `encrypt` и перемешивает ее.

3. Выдача карты игроку:
   - для выбранной зашифрованной карты каждый игрок (кроме владельца карты) снимает свой слой шифрования;
   - владелец снимает последний слой своим ключом и получает открытый `cardId`.

4. Общие карты:
   - аналогично снимаются слои для публичного раскрытия на стол.

5. Проверяемость:
   - по возможности добавляются доказательства корректности шагов (или протокол аудита/логирования действий).
